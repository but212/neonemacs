# neonemacs 기능 명세

> 독자: 사용자와 구현자

## 1. 정체성

- Emacs 키 감각을 가진 경량 터미널 편집기다.
- Emacs 구현의 코드, 형식, 매크로 문법과 호환하지 않는다. 키와 명령 이름은 Emacs 관례를 따른다.
- 목표: 가볍고, 저장 사고가 없고, UTF-8과 한글을 정확히 다룬다.
- 키는 생존 집합만 두고, 나머지는 `M-x`로 호출한다 (3절, 4절).

## 2. 구현 기준

- **언어**: Rust.
- **아키텍처**: 함수형 코어 / 명령형 쉘 (Functional Core, Imperative Shell, ADR 0002).
  - `src/core`: I/O 부수효과를 일절 포함하지 않는 순수 상태 전이 기계. 모든 함수 시그니처에서 `&mut`를 금지하며 값 전달(`mut self -> Self`)로만 전이한다 (I-18). 대규모 파일 편집 시에도 버퍼 전체를 깊은 복사하지 않고 소유권 이동(`with_buffer`)을 통해 $O(1)$로 전이하여 입력 지연을 방지한다.
  - **상태 캡슐화**: `Editor`와 `Buffer`의 모든 상태 필드는 비공개로 은닉되며, 쉘과 내장 명령 모두 순수 도메인 전이 메서드만을 통해 상태를 변경한다 (I-25).
  - `src/shell`: 터미널(crossterm), 파일 시스템, 백그라운드 셸 프로세스, Lua 런타임 등 외부 부수효과를 전담 수행한다 (I-15). 코어가 발행하는 모든 `Effect`(파일/WAL I/O 등)는 쉘이 처리하고 단일 `Event`로 응답한다.
- **확장**: Lua 임베딩. Emacs 매크로 문법은 지원하지 않는다.
- **플랫폼**: Linux, macOS, Windows.
- **바이너리**: 릴리스·strip 기준 5MB 이하 (Linux x86_64).

## 3. 키 체계

- 키는 아래 표만 제공한다. 나머지 기능은 `M-x`로 호출한다 (4절). 키 호환은 이 범위에서만 보장한다.
- 터미널 흐름 제어(XON/XOFF)는 끈다. 그래야 `C-s`를 쓸 수 있다.

| 기능 | 키 |
| --- | --- |
| 파일 열기 | `C-x C-f` |
| 저장 | `C-x C-s` |
| 종료 (미저장 변경이 있으면 확인) | `C-x C-c` |
| 이동 | `C-f` `C-b` `C-n` `C-p`, `C-a` `C-e`, 방향키 |
| 삭제 | Backspace, `C-d` |
| 마크 (영역 시작) | `C-SPC` |
| 잘라내기 / 복사 / 붙여넣기 | `C-w` / `M-w` / `C-y` |
| 실행 취소 | `C-/`, `C-_` |
| 앞으로 증분 검색 | `C-s` |
| 명령 실행 | `M-x` |
| 취소 | `C-g` |

## 4. 명령 실행 (M-x)

- 명령 이름을 입력하는 동안 자동완성을 보여 준다. 명령 목록에는 연결된 키를 함께 표시하고, 키가 없으면 비워 둔다.
- 명령 이름은 Emacs 이름을 따른다. Emacs에 없는 고유 명령은 `동사-대상` 형식으로 정한다.
- 내장 명령 테이블은 알파벳순으로 정렬되어 있으며, 이름으로 디스패치된다.
- 키가 없는 기능의 명령 이름은 아래와 같다.

| 기능 | 명령 이름 |
| --- | --- |
| 뒤로 검색 | `isearch-backward` |
| 정규식 앞으로 / 뒤로 검색 | `isearch-forward-regexp` / `isearch-backward-regexp` (9절) |
| 치환 (확인하며 바꾸기) | `query-replace` |
| 정규식 치환 | `query-replace-regexp` (9절) |
| 줄 번호로 이동 | `goto-line` |
| 버퍼 전환 / 닫기 | `switch-to-buffer` / `kill-buffer` |
| 창 나누기 (위아래 / 좌우) | `split-window-below` / `split-window-right` |
| 나머지 창 닫기 / 다음 창 | `delete-other-windows` / `other-window` |
| 줄 끝까지 잘라내기 | `kill-line` |
| 문단 다시 채우기 | `fill-paragraph` |
| 다른 이름으로 저장 | `write-file` |
| 다시 읽기 | `revert-buffer` |
| 줄 끝 방식 전환 (LF / CRLF) | `toggle-eol` (8절) |
| 커서와 마크 위치 교환 | `exchange-point-and-mark` |
| 셸 명령 실행 | `shell-command` |
| 잘라낸 텍스트 순환 | `yank-pop` |
| 실행 취소 (키 없이) | `undo` |
| 보기 전용 켜기 / 끄기 | `view-mode` (10절) |

- **비동기 셸 명령 (`shell-command`)**: 백그라운드 스레드로 실행되어 터미널 UI를 차단하지 않는다.
  - 실행 중에는 에코 영역에 회전 스피너(`[Running... |]`)가 표시된다.
  - 이미 명령이 실행 중일 때 추가 실행은 스피너와 함께 차단 안내(`A shell command is already running`)가 표시되며 중복 생성을 막는다.
  - 프롬프트(`M-x`, 파일 열기 등)나 증분 검색(`C-s`, `isearch`) 진입 중이거나 상태 알림 표시 중에는 사용자 입력을 방해하지 않도록 스피너 갱신을 유예하며, 완료 결과는 안전하게 반영된다.
  - 작업 스레드가 비정상 단절(패닉 등)되어도 에코 영역이 `[Running...]`에 고착되지 않고 비정상 종료 오류를 즉시 보고한다.

## 5. 화면과 창

- 여러 버퍼를 동시에 연다. 버퍼마다 커서 위치와 마크를 따로 기억한다.
- 창을 나누면 같은 버퍼를 두 곳에서 볼 수 있다. 창마다 커서가 독립적이다.
- 버퍼 전환과 창 나누기는 `M-x`로만 접근한다 (4절).
- **버퍼와 창 생존 불변식**: 최소 1개의 버퍼가 항상 존재한다. 마지막 버퍼를 닫으면 자동으로 빈 `*scratch*` 버퍼가 생성된다. 모든 창은 항상 살아 있는 버퍼만을 참조하며, 특정 버퍼를 닫을 때 해당 버퍼를 보던 모든 창은 다른 살아 있는 버퍼(또는 새로 생성된 `*scratch*`)로 즉시 안전하게 전환된다. 현재 선택된 창 인덱스는 항상 유효한 분할 창 범위 내로 제한된다.
- 상태 줄에 파일 이름, 상태(변경됨, 보기 전용), 줄 끝 방식(LF, CRLF), 위치 백분율을 보여 준다. 폭이 모자라면 줄 끝 방식부터 생략한다.
- **경량 구문 강조**: 주요 프로그래밍 언어(Rust, C, Python, JS, Lua, Go, Markdown)의 키워드, 문자열, 주석, 숫자를 1-pass로 토큰화하여 ANSI 색상으로 표시한다. 전각 문자(한글·CJK) 및 결합문자의 표시 폭을 반영하여 화면 격자 셀과 커서 위치를 유지하며, 텍스트뿐만 아니라 구문 강조 스타일만 변경된 행도 감지하여 화면을 차등 갱신한다.
- **대용량 파일 탐색 및 스크롤 성능**: 갭 버퍼의 물리적 2-슬라이스(`slices`)와 SIMD 벡터화(`memchr`)를 결합하여 개행(`\n`) 탐색(`line_start`, `line_end`, `nth_line_start`, `count_lines`)을 초고속으로 수행한다. 화면 스크롤 시 상단과 커서 사이의 줄 수 계산(`scroll_window`) 역시 `count_lines` 단일 SIMD 스캔으로 처리되어 수십 MB 대용량 파일에서도 $O(N)$ 바이트 반복 지연 없이 화면을 갱신한다.
- 입력에 지연이 없어야 한다. 느린 원격 연결에서도 화면 갱신이 실용적인 속도로 끝나야 한다.
- 터미널 크기가 바뀌면 화면을 새 크기에 맞춰 다시 배치한다.

## 6. 편집

- 삽입이 기본이자 유일한 입력 방식이다. 덮어쓰기 모드는 없다.
- `C-SPC`로 마크를 찍으면 마크와 커서 사이가 영역이다. `C-w`, `M-w`, `C-y`로 잘라내기, 복사, 붙여넣기를 한다. 잘라낸 텍스트 순환(`yank-pop`)은 `M-x`로 호출한다.
- **킬 링(KillRing) 불변식**: 잘라낸 텍스트 이력은 독립된 `KillRing` 타입으로 캡슐화되어 관리된다 (I-26). 연속된 `kill-line` 등은 마지막 킬 항목에 이어 붙이고(`append_last`), `yank-pop`은 링을 1칸 순환(`rotate_right`)시킨다. 원시 바이트 목록에 대한 외부 직접 변이는 배제된다.
- 줄 끝까지 잘라내기(`kill-line`)와 문단 재정렬(`fill-paragraph`)은 `M-x`로 호출한다. 채움 열은 설정 값으로 지정한다.
- **커서 및 앵커 불변식**: 커서와 마크는 모든 이동과 편집 상태 전이에서 항상 버퍼 범위(0..=길이) 내의 유효한 문자 경계에만 놓인다. 다중 바이트 문자 중간이나 버퍼 범위를 벗어나는 커서 상태는 데이터 구조와 전이 생성자 수준에서 원천적으로 배제된다.

## 7. 실행 취소 및 크래시 복구

- **메모리 내 undo**: 편집 단위로 되돌린다. 키는 `C-/`와 `C-_`다. 터미널이 둘 중 하나만 보내도 동작해야 한다.
- **Emacs 방식**: 다시 실행 키는 두지 않는다. 실행 취소를 다시 실행 취소하면 앞 상태로 돌아간다.
- **영속 undo**: 저장할 때 undo 기록을 원본 옆 `.<원본이름>.undo`에 남긴다. 다시 열면 기록을 읽어 되돌릴 수 있다. 기록이 원본과 맞지 않으면(mtime 또는 크기 불일치) 무시한다.
- **크래시 복구 (WAL)**: 실제 파일에 연결된 버퍼에 미저장 변경이 발생한 후 1초간 유휴 상태가 지속되면 백그라운드로 `.<원본이름>.wal`에 안전하게 영속화한다.
  - **원자적 격리 및 디스크 동기화**: 임시 파일 생성 시 프로세스 ID와 고유 시퀀스를 결합(`.{name}.{pid}_{seq}.wal.tmp`)하여 다중 스레드·프로세스 간 충돌을 방지하며, `sync_all`로 디스크에 강제 플러시한 후 원자적 교체(`rename`)를 수행하여 커널 패닉이나 정전 시 0바이트 또는 손상 파일이 남는 것을 원천 방지한다.
  - **엄격한 디스크 일치 검증**: WAL 파일은 원본 파일의 디스크 상태(mtime, 크기)와 버전 스키마를 포함한다. 기존 파일(tag 1, `Known`)과 신규 파일 버퍼(tag 0, `Unknown`)의 상태를 엄격히 대조하여, 비정상 종료 후 원본이 외부에서 수정·삭제되었거나 신규 파일 경로에 파일이 생성된 경우 복구를 거부하고 외부 데이터를 보존한다. 손상된 타임스탬프(`nanos >= 1_000_000_000`)는 패닉 없이 즉시 기각된다.
  - **수명주기 즉시 해제 (I-25)**: 정상 저장(`C-x C-s`), 다시 읽기(`revert-buffer`), 버퍼 닫기(`kill-buffer`), 다른 이름으로 저장(`write-file`), 또는 미저장 종료 확인(`QuitUnsaved`)으로 변경이 해소되거나 대상 경로가 변경되면 코어가 `Effect::RemoveWal`을 발행하여 해당 경로의 WAL 파일을 즉시 삭제한다. 특히 `write-file` 시 이전 파일의 잔여 WAL이 디스크에 고아 파일로 방치되지 않도록 새 파일 경로로의 전환 전에 이전 경로의 WAL을 선행 정리한다.
  - **커서/앵커 정규화 (I-01)**: WAL 복구 시 내용이 축소되거나 변경되더라도 버퍼의 커서 위치(`saved_point`)와 마크(`mark`)를 복원된 텍스트 경계로 자동 스냅(`snap_anchors`)하여 커서 불변식을 보존한다.
  - **줄 끝 방식**: WAL은 줄 끝 방식을 저장하지 않는다. 복구된 버퍼는 디스크 파일을 열 때 정한 방식을 쓰므로, `toggle-eol`로 바꾼 방식은 비정상 종료 후 사라진다. 텍스트는 `\n`으로 복구되므로 내용은 잃지 않는다.

## 8. 파일 입출력과 안전

- 열기, 다시 읽기, 저장, 다른 이름으로 저장을 지원한다. 다시 읽기와 다른 이름으로 저장은 `M-x`로 호출한다 (`revert-buffer`, `write-file`).
- **원자적 저장 (`atomic_write`)**: 모든 디스크 쓰기(일반 저장, 영속 undo, WAL)는 `src/shell/atomic.rs`를 통해 원자적으로 수행된다. 심볼릭 링크를 추적하여 실제 타겟 파일 경로를 찾고, PID와 시퀀스로 격리된 임시 파일을 생성하여 내용을 기록한 뒤 `sync_all`로 플러시하고 `rename`으로 교체한다. 오류 발생 시 임시 파일은 즉시 정리된다.
- **다른 이름으로 저장 (`write-file`)**: 버퍼의 백킹 파일 경로를 새 경로로 변경하고 저장한다. 이전 파일 경로에 유휴 WAL이 존재하면 저장 전에 즉시 삭제하여 고아 파일 발생 및 추후 파일 재오픈 시의 잘못된 세션 복구를 방지한다.
- **읽기**: UTF-8로 읽는다. 잘못된 바이트는 1바이트 Latin-1 문자로 보존해 내용이 사라지지 않게 한다.
- **줄 끝 방식 (LF / CRLF)**: 버퍼마다 하나다 (`LF` 또는 `CRLF`). 파일을 열 때 `\r\n` 쌍의 개수와 순수 `\n` 개수를 비교하는 다수결로 결정한다 (동률이거나 개행이 없으면 LF 기본).
  - **메모리 정규화 불변식**: 버퍼 텍스트 안에는 항상 `\n`만 둔다. 파일을 읽을 때 `\r\n` 쌍에서 `\r`을 모두 제거하며, 개행과 무관한 단독 `\r`은 일반 문자로 보존한다. 입력, 렌더링, 검색은 줄 끝 방식과 관계없이 순수 `\n` 기준으로 일관되게 동작한다.
  - 저장할 때 CRLF 버퍼는 모든 `\n` 앞에 `\r`을 붙이고, LF 버퍼는 텍스트 바이트(`\n`)를 그대로 쓴다. 혼합 개행 파일은 저장 시 해당 버퍼의 방식(LF 또는 CRLF)으로 일괄 통일된다.
  - 다른 이름으로 저장은 버퍼의 방식을 유지한다. 다시 읽기는 디스크의 바이트로 방식을 다시 정한다.
- **줄 끝 전환 (`toggle-eol`)**: 버퍼의 줄 끝 방식을 뒤집는다 (`LF <-> CRLF`). 텍스트는 바뀌지 않고 버퍼는 변경됨으로 표시된다. undo 기록에는 들어가지 않는다. 메모리 텍스트는 항상 순수 `\n`으로 정규화되어 있으므로 어떠한 버퍼에서도 조건 없이 항상 전환할 수 있다.
- **잘린 파일**: 크기 제한으로 잘린 파일은 저장할 때 한 번 확인받는다. 잘린 파일도 읽어들인 바이트 범위 내에서 다수결로 줄 끝 방식을 판별하고 `\n`으로 정규화한다.
- **외부 변경**: 열 때 기록한 mtime과 크기가 디스크와 다르면 저장할 때 덮어쓸지 묻는다. 크기는 줄 끝을 정규화하기 전 원본 바이트 수로 비교한다. 이 편집기가 방금 저장한 결과는 외부 변경이 아니다. 이전 상태를 확인할 수 없으면 변경으로 보지 않고 저장한다.
- **종료** (`C-x C-c`): 미저장 변경이 있으면 확인한다.
- **파일 잠금 없음**: 잠금 파일을 만들지 않으며 "File in use" 질문도 없다.

## 9. 검색과 치환

- 기본은 문자열 증분 검색이다. `C-s`로 앞으로 찾는다. 글자를 칠 때마다 이동하고, `C-s`를 다시 누르면 다음 일치로 간다.
- 뒤로 검색(`isearch-backward`)과 치환(`query-replace`)은 `M-x`로 호출한다.
- 대소문자 구분과 정규식은 모드가 아니라 명령으로 고른다. 정규식 명령은 `isearch-forward-regexp`, `isearch-backward-regexp`, `query-replace-regexp`다. 대소문자는 설정 `case-fold-search`(기본 `true`)로 정한다. 키 바인딩은 Lua로 바꾼다.
- 정규식: `.`, `[...]`, `[^...]`, `*`(바로 앞 원소 반복), `^`, `$`. 일치는 한 줄 안에서만 한다. 치환 문자열의 `&`는 일치한 문자열 전체로 바뀐다. 정규식이 아닌 치환(`query-replace`)에서는 `&`와 `\&`가 그대로 문자다. 정규식 치환(`query-replace-regexp`)에서는 `\&`가 `&` 문자다.

## 10. 보기 전용

- 모드 시스템은 없다. 대소문자와 정규식은 9절의 명령 인자다.
- **보기 전용 플래그**: 버퍼마다 하나다. 켜면 내용을 바꿀 수 없다. `view-mode`로 켜고 끄며, 키는 두지 않는다. 상태 줄에 표시한다. 보기 전용 버퍼에서는 `toggle-eol`도 거부한다.
- 시작 옵션 `-v`는 없다. 파일을 연 뒤 `view-mode`를 호출한다.

## 11. 한글과 UTF-8

- 읽기: UTF-8. 과도하게 긴 형식도 읽는다. 저장: 읽은 바이트는 그대로 저장한다. 입력한 문자는 가장 짧은 표준 형식으로 인코딩한다.
- 커서는 문자 경계를 따라 움직인다. 한 글자가 여러 바이트여도 중간에 멈추지 않는다.
- 표시 폭:
  - 탭은 다음 탭 위치까지 차지한다.
  - 제어 문자는 2칸, C1 제어 문자(0x80~0x9F)는 3칸이다.
  - 한글, CJK 등 전각(East Asian Wide/Fullwidth) 문자는 2칸이다.
  - 결합 문자(Mn, Me), 한글 자모 중성·종성(U+1160~11FF), ZWJ 등은 0칸이다. 커서는 문자 단위로 움직인다.
  - 그 밖의 문자는 1칸이다.
- 줄 끝 방식(8절)은 표시 폭에 영향이 없다. 텍스트에는 `\n`만 남는다.

## 12. 확장과 설정 (Lua)

- 설정과 확장은 Lua로 한다. 파일은 `~/.config/neonemacs/init.lua`이며, `XDG_CONFIG_HOME`이 있으면 `$XDG_CONFIG_HOME/neonemacs/init.lua`다. 세 플랫폼 모두 같은 규칙이다.
- **공개 API는 최소로 한다.** 공개한 API는 호환성 약속이다 (ADR 0001, ADR 0004, ADR 0005).
  - `bind(keys, command)`: 키 바인딩 추가와 변경
  - `unbind(keys)`: 키 바인딩 제거
  - `command(name, function)`: 명령 등록
  - `run(name)`: 명령 실행
  - `get(name)` / `set(name, value)`: 설정 값 읽기와 쓰기
  - `syntax.register(name, spec)`: 구문 강조 규칙 등록 (확장자 목록, 주석 기호, 키워드 목록 선언적 테이블 등록)
- 기본 구문 강조(`syntax.lua`) 및 표준 확장 키바인딩(`keymap.lua`: `C-k`, `C-x 2`, `C-x 3`, `C-x 1`, `C-x o`, `C-x b`, `C-x k`, `C-x C-w`, `C-x C-q`, `C-x u`, `M-q`, `M-y`, `C-r`, `M-%`, `M-g`, `M-!`)는 바이너리 내장 스크립트로 제공되며, `init.lua` 실행 전에 부트스트랩되어 사용자 설정에서 자유롭게 재정의하거나 해제할 수 있다.
- 버퍼 텍스트, 이벤트 훅, 버퍼·창·파일 시스템은 공개하지 않는다.
- 생존 집합 밖의 키는 Lua 설정으로 추가할 수 있다.

### 시작 방식

- 파일 인자는 모두 백그라운드 버퍼로 열고, 첫 번째 파일을 화면에 보인다.
- 유일한 시작 옵션은 `+n`(n번째 줄에서 열기)이다. `+n`은 바로 뒤에 오는 파일 인자에 적용된다.
  - `n`은 1 이상의 정수여야 한다 (`n >= 1`).
  - 유효하지 않은 줄 번호(`+0`, `+-1`, 문자열, 오버플로우 등)이거나 `+n` 뒤에 파일 인자가 없으면 `neonemacs: ...` 에러를 표준 에러(stderr)에 출력하고 종료 코드 `2`로 즉시 종료한다.
- 시작 시 각 파일에 유효한 미저장 WAL이 존재하고 디스크 상태(mtime, 크기)가 일치하면 순수 도메인 전이를 통해 내용을 자동 복구하며, `[Recovered <파일이름> from WAL]` 알림을 표시한다 (7절, I-23). 시작 옵션 `+n`과 결합 시에도 복구된 텍스트 길이에 맞게 커서가 안전하게 정규화된다. 손상되거나 디스크 상태가 맞지 않는 WAL은 안전하게 무시한다.
- `init.lua`가 있으면 시작할 때 자동 실행한다. 설정 스크립트에 문법/런타임 오류가 발생해도 프로세스가 중단되지 않으며 에코 영역에 `init.lua: <오류>` 안내를 남긴다.
- `@파일`과 `-v`는 없다. 보기 전용은 `view-mode`로 연다 (10절).

## 13. 플랫폼

- Linux, macOS, Windows를 지원한다 (2절).
- Windows 콘솔은 `C-_`, `C-/`, `C-SPC`를 POSIX 터미널과 다르게 보낼 수 있다. 생존 집합 키는 세 플랫폼 모두에서 같은 동작을 해야 한다.
- **터미널 수명주기와 안전한 복원 (RAII & Panic Hook)**:
  - 터미널 원시 모드(Raw Mode)와 대체 화면(Alternate Screen)은 `TerminalGuard` RAII 수명주기로 관리되어, 정상 종료뿐만 아니라 조기 오류 반환 시에도 확실하게 원래 상태로 복원된다.
  - 패닉 발생 시 표준 패닉 메시지가 출력되기 전에 터미널 화면과 커서, 원시 모드를 선행 복원하여 셸 환경이 파손되는 것을 원천 방지한다 (§13).
- 런타임 I/O 실패나 비정상 오류는 메시지를 남기고 종료 코드 `1`로 종료한다.

## 14. 동작 원칙

1. **단순함과 이식성을 우선한다.** 기능보다 크기와 이식성을 지킨다.
2. **인지 부하를 줄인다.** 키는 적게 두고, 나머지는 익숙한 Emacs 명령 이름으로 `M-x`에서 부른다. 새 규칙은 Emacs에 없을 때만 도입한다.
3. **입력에 지연이 없어야 한다.**
4. **저장 전에 묻는다.** 잘린 파일, 외부 변경, 미저장 종료는 먼저 묻는다.
5. **판단할 수 없으면 막지 않는다.** 이전 상태를 알 수 없는 파일은 차단하지 않고 저장한다.
6. **저장 사고를 막는다.** 저장 전 편집 기록은 영속 undo로 남긴다.
7. **데이터 불변식을 지킨다.** 버퍼 풀의 최소 버퍼 보장, 창 분할 트리의 선택 유효성, UTF-8 및 커서 경계, 단일 키/접두사 정규 키 시퀀스, 크래시 복구 바이너리 스키마, 원자적 디스크 동기화(`sync_all`) 및 임시 파일 PID/시퀀스 격리, `write-file` 시 이전 WAL 고아 방지, `Editor` 필드 전면 캡슐화(I-25), `KillRing` 무결성(I-26), 코어 시그니처 `&mut` 배제(I-18), 시작 인자 검증 및 터미널 RAII 복원 등 모든 도메인 규칙을 데이터 구조와 타입 수준에서 강제하여 불가능한 상태 전이와 패닉을 원천 배제한다.

## 15. 한계와 주의점

- Emacs와 독립된 편집기다. Emacs 구현의 매크로 문법과 호환되지 않는다.
- 키 호환은 3절(생존 집합) 및 번들 `keymap.lua` 범위에서 보장한다.
- `C-/`는 많은 터미널에서 `C-_`로 전송된다. 그래서 두 키를 함께 바인딩한다.
- 영속 undo는 저장된 이력만 보존하며, 미저장 편집은 WAL(§7)이 복구한다.
- `toggle-eol`은 undo와 WAL에 기록되지 않는다. 비정상 종료 후에는 디스크 파일의 줄 끝 방식으로 돌아간다.
- 한글 IME 조합 표시는 터미널에 따라 다르다.
