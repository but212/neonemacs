# neonemacs 기능 명세

> 독자: 사용자와 구현자

## 1. 정체성

- Emacs 키 감각을 가진 경량 터미널 편집기다.
- Emacs 구현의 코드, 형식, 매크로 문법과 호환하지 않는다. 키와 명령 이름은 Emacs 관례를 따른다.
- 목표: 가볍고, 저장 사고가 없고, UTF-8과 한글을 정확히 다룬다.
- 키는 생존 집합만 두고, 나머지는 `M-x`로 호출하거나 Lua 설정으로 확장한다 (3절, 4절, 12절).

## 2. 구현 기준

- **언어**: Rust.
- **아키텍처**: 함수형 코어 / 명령형 쉘 (Functional Core, Imperative Shell).
  - **코어 (`src/core`)**: I/O 부수효과를 포함하지 않는 순수 상태 전이 기계다. 모든 시그니처에서 가변 참조(`&mut`)를 배제하고 값 소유권 전이(`Editor -> Editor`, `Buffer -> Buffer`, `WindowManager -> WindowManager`)로만 상태를 갱신하여 대규모 버퍼에서도 딥클론과 입력 지연을 원천 배제한다.
  - **쉘 (`src/shell`)**: 터미널, 파일 시스템, 백그라운드 프로세스, Lua 런타임(`RefCell::take` 소유권 이동 브리지), 시작 오케스트레이션(`shell::startup`) 등 외부 부수효과를 전담한다. 코어가 발행한 효과 요청(`Effect`)을 실행하고 단일 이벤트(`Event`)로 응답한다.
- **확장**: Lua 임베딩. Emacs 매크로 문법은 지원하지 않는다.
- **플랫폼**: Linux, macOS, Windows.
- **MSRV**: Rust 1.88 (`Cargo.toml`의 `rust-version`).
- **바이너리**: 릴리스·strip 기준 5MB 이하 (Linux x86_64).

## 3. 키 체계

- 키는 아래 표만 기본 제공하며, 나머지는 `M-x`로 호출하거나 번들 키맵으로 확장한다 (4절, 12절). 키 호환은 이 범위에서만 보장한다.
- `C-s` 사용을 위해 터미널 흐름 제어(XON/XOFF)를 끈다.

| 기능 | 키 |
| --- | --- |
| 파일 열기 | `C-x C-f` |
| 저장 | `C-x C-s` |
| 종료 (미저장 변경이 있으면 확인) | `C-x C-c` |
| 이동 | `C-f` `C-b` `C-n` `C-p`, `C-a` `C-e`, 방향키 |
| 삭제 | Backspace, `C-d` |
| 잘라내기 / 복사 / 붙여넣기 | `C-w` / `M-w` / `C-y` |
| 실행 취소 | `C-/`, `C-_` |
| 앞으로 증분 검색 | `C-s` |
| 명령 실행 | `M-x` |
| 취소 | `C-g` |

- 번들 키맵은 `C-l`을 `recenter`에 연결한다.
- 접두 키(`C-x`, `Esc`)나 `Ctrl`/`Alt`와 함께 눌린 문자 키가 바인딩에 없으면, 자판 별칭(12절 `key_alias`)으로 바꾼 키로 한 번 더 찾는다. 번들 별칭이 두벌식 자모를 QWERTY 키로 바꾸므로 한글 상태에서도 `C-x ㅠ`가 `C-x b`로, `Alt+ㅌ`와 `Esc ㅌ`가 `M-x`로 동작한다. 명시 바인딩이 먼저이고, 일반 글자 입력에는 적용하지 않는다.
- 마크 설정(`set-mark-command`)에는 기본 키가 없으며 `M-x`로 호출하거나 `bind`로 직접 연결한다. `C-SPC`는 입력기와, `C-v`는 터미널 붙여넣기와, `M-f`/`M-v`는 터미널 메뉴 접근 키와 충돌할 수 있어 기본 제공하지 않는다.

## 4. 명령 실행 (M-x)

- 명령 이름 입력 중 자동완성을 표시한다. 내장 명령과 Lua 등록 명령을 알파벳순으로 통합 정렬하여 바인딩된 키와 함께 보여 주고, 키가 없으면 비워 둔다.
- 명령 이름은 Emacs 관례를 따르며, 고유 명령은 `동사-대상` 형식을 쓴다.

| 기능 | 명령 이름 |
| --- | --- |
| 뒤로 검색 | `isearch-backward` |
| 정규식 앞으로 / 뒤로 검색 | `isearch-forward-regexp` / `isearch-backward-regexp` (9절) |
| 치환 (확인하며 바꾸기) | `query-replace` |
| 정규식 치환 | `query-replace-regexp` (9절) |
| 줄 번호로 이동 | `goto-line` |
| 버퍼 전환 / 닫기 | `switch-to-buffer` / `kill-buffer` |
| 창 나누기 (위아래 / 좌우) | `split-window-below` / `split-window-right` |
| 나머지 창 닫기 / 다음 창 | `delete-other-windows` / `other-window` |
| 줄 끝까지 잘라내기 | `kill-line` |
| 문단 다시 채우기 | `fill-paragraph` |
| 다른 이름으로 저장 | `write-file` |
| 다시 읽기 | `revert-buffer` |
| 줄 끝 방식 전환 (LF / CRLF) | `toggle-eol` (8절) |
| 커서와 마크 위치 교환 | `exchange-point-and-mark` |
| 셸 명령 실행 | `shell-command` |
| `init.lua` 다시 읽기 | `reload-init` (12절) |
| 잘라낸 텍스트 순환 | `yank-pop` |
| 실행 취소 (키 없이) | `undo` |
| 보기 전용 켜기 / 끄기 | `view-mode` (10절) |
| 커서 줄을 화면 중앙으로 | `recenter` |

- **비동기 셸 명령 (`shell-command`)**: 백그라운드 스레드에서 실행되어 터미널 UI를 차단하지 않는다.
  - 실행 중 에코 영역에 회전 스피너(`[Running... |]`)를 표시하며, 중복 실행 요청은 차단 안내와 함께 거부한다.
  - 프롬프트·증분 검색 진입 중이거나 일반 상태 메시지가 떠 있을 때는 스피너 갱신을 유예하며, 완료 시 결과를 반영한다.
  - 실행 스레드가 비정상 종료되어도 에코 영역이 고착되지 않고 즉시 오류를 보고한다.

## 5. 화면과 창

- 여러 버퍼를 동시에 열며, 버퍼마다 커서(`saved_point`)와 마크(`mark`)를 따로 기억한다.
- 창을 나누면 같은 버퍼를 여러 곳에서 볼 수 있고, 창마다 커서(`point`)와 스크롤 상단(`top`)이 독립적이다.
- **버퍼와 창 생존 불변식**: 최소 1개의 버퍼가 항상 존재한다. 마지막 버퍼를 닫으면 빈 `*scratch*` 버퍼를 자동 생성하며, 닫힌 버퍼를 보던 모든 창은 살아 있는 대체 버퍼로 즉시 전환된다.
- 상태 줄에 파일 이름, 상태(변경됨, 보기 전용), 줄 끝 방식(LF, CRLF), 커서 위치 `줄:열`, 위치 백분율을 표시한다. 줄과 열은 1부터 세며 열은 표시 열이다(탭과 전각 문자 반영). 폭이 부족하면 줄 끝 방식, 백분율 순으로 생략한다.
- **강조와 접두 키 (I-47)**: 선택 창은 활성 영역(마크와 커서 사이)과 증분 검색·치환의 현재 일치를 반전 표시한다. 다른 창에는 표시하지 않는다. `C-x` 또는 `Esc` 접두 키를 기다리는 동안 에코 영역에 `C-x-` 또는 `ESC-`를 보여 주고, 시퀀스가 끝나면 원래 메시지로 돌아온다.
- **화면 재중앙화**: 창은 마지막 배치의 본문 행 수 `H`를 기억한다(첫 화면 전에는 0). `recenter`는 텍스트와 커서를 바꾸지 않고 커서 줄을 `H / 2`번째 행에 놓으며, 버퍼 앞부분에서는 `top`을 0으로 맞춘다.
- **경량 구문 강조**: 키워드(Cyan), 타입(Magenta), 문자열(Green), 주석(DarkGrey), 숫자(Yellow)를 $O(\log K)$ 이진 탐색 기반 단일 패스 렉서로 토큰화한다. 렌더링 격자(`Frame`)는 순수 글리프와 스타일 토큰만 유지하고 터미널 출력 시점에만 ANSI 시퀀스를 주입하여 전각 문자(한글·CJK) 표시 폭과 커서 좌표를 정확히 유지하며, 변경된 행만 차등 갱신한다.
- **대용량 파일 탐색 성능**: 슬라이스 기반 개행 탐색과 줄 단위 단어 스캔으로 수십 MB 파일에서도 입력·화면 갱신 지연이 없다.
- 터미널 크기가 바뀌면 화면을 새 크기에 맞춰 재배치한다.

## 6. 편집

- 삽입이 유일한 입력 방식이며 덮어쓰기 모드는 없다.
- `expand-tabs`(기본 꺼짐)를 켜면 키보드 TAB이 `tab-width`의 다음 탭 위치까지 공백을 한 번의 편집으로 삽입한다. 붙여넣기, 기존 탭, Lua 삽입은 바꾸지 않는다.
- **프롬프트 편집**: 입력 중 `C-b` / `left`, `C-f` / `right`로 커서를 옮기고, `C-a` / `home`, `C-e` / `end`로 양끝에 가며, Backspace는 커서 앞 문자, `C-d`는 커서 위치 문자를 지운다. 입력은 커서 위치에 삽입되고 TAB 완성은 커서를 끝으로 보낸다. 에코 영역 커서는 전각 폭을 반영하며, 입력이 폭을 넘으면 커서가 보이도록 뒤쪽을 보여 준다.
- `set-mark-command`로 마크를 찍으면 마크와 커서 사이가 영역이다. `C-w`, `M-w`, `C-y`로 잘라내기, 복사, 붙여넣기를 수행하고 `yank-pop`으로 순환한다. 연속된 잘라내기는 하나의 킬 항목으로 병합된다.
  - 킬 링은 최대 `kill-ring-max`(기본 120)항목을 유지한다. 넘치면 가장 오래된 항목부터 버린다.
  - `yank-pop`은 `C-y` 직후에만 동작한다. 그 사이에 텍스트가 바뀌면 `Previous command was not a yank`를 띄우고 아무것도 바꾸지 않는다.
  - 마크는 `set-mark-command`(또는 Lua `buffer.set_mark`)로 찍으면 활성이다. 텍스트 편집, `C-g`, `M-w`는 마크를 비활성으로 바꾸며 위치는 남는다. 비활성 마크는 표시되지 않고 `exchange-point-and-mark`에서만 쓰인다.
- **파레토 핵심 텍스트 편집 명령**:
  - 단어 이동 및 삭제: `forward-word`, `backward-word`, `kill-word`, `backward-kill-word`
  - 버퍼 양끝 이동: `beginning-of-buffer`, `end-of-buffer`
  - 문단 재정렬: `fill-paragraph` (`fill-column` 너비 기준)
  - 주석 토글: `comment-dwim` (언어별 주석 기호 감지 및 영역/단일행 토글)
  - 전체 선택: `mark-whole-buffer`
- **커서 및 앵커 불변식**: `Buffer` 필드는 비공개로 캡슐화되며, 모든 이동·편집·복구·Lua 변이 전이(`set_mark`, `set_saved_point`, `apply_edit`, `with_window`, `snap_windows_for_buffer`)는 커서와 마크를 버퍼 범위(`0..=len`) 내 유효한 문자(Unit) 경계로 강제 스냅한다.

## 7. 실행 취소 및 크래시 복구

- **메모리 내 undo**: 편집 단위로 되돌린다 (`C-/`, `C-_`). 연속 글자 입력(`self-insert`)은 최대 20글자까지 하나의 undo 그룹으로 묶이며, 비-삽입 명령이 시작될 때 직전 타이핑 그룹을 즉시 닫아 삭제·주석 토글 등이 직전 타이핑과 섞이지 않게 보장한다.
- **저장 상태로 복귀 (I-41)**: 저장 직후의 텍스트에서 시작한 편집 단위를 모두 되돌리면 수정됨 표시가 해제되고 그 파일의 WAL이 삭제된다. 수정된 텍스트에서 시작한 단위는 해제하지 않는다(수정됨 쪽으로만 틀린다). undo 상한으로 단위가 버려졌거나 텍스트가 통째로 교체된 뒤에는 저장 텍스트와 같아도 수정됨으로 남는다.
- **Emacs 방식**: 별도 Redo 상태를 두지 않는다. 실행 취소를 역방향 편집으로 기록하여, 다른 명령 후 다시 실행 취소하면 앞 상태로 돌아간다.
- **상한**: undo 상한은 `undo-limit` 설정 하나뿐이며 모든 버퍼에 같은 값이 적용된다. 텍스트를 편집 명령 밖에서 통째로 바꾸면(셸 출력 버퍼 갱신, WAL 복구, 다시 읽기) 그 버퍼의 undo 기록은 비워진다.
- **크래시 복구 (WAL)**: 파일 연결 버퍼(`Backing::File`)에서 실제 텍스트 편집이 발생한 후 1초간 유휴 상태가 지속되면 `.<원본이름>.wal`에 영속화한다.
  - WAL 더티 상태(`wal_dirty`)는 `Backing::File`과 `Backing::Scratch`에만 존재하므로 그 밖의 파일 없는 버퍼(`*Shell Command Output*`, `*init-log*` 등)나 단순 커서 이동은 디스크 쓰기를 유발하지 않는다. `*scratch*`는 아래 scratch 슬롯에 기록한다.
  - 임시 파일 기록 후 디스크 동기화(`sync_all`)와 원자적 이름 변경으로 교체한다.
  - 원본 파일의 디스크 상태(수정 시각, 크기)가 WAL 기록 시점과 다르면 복구를 거부하고 디스크 원본을 보존한다.
  - 정상 저장, 다시 읽기, 버퍼 닫기, 다른 이름으로 저장, 미저장 종료 확인 시 잔여 WAL 파일을 즉시 삭제한다.
  - WAL 복구(`Editor::restore_buffer_content`)는 텍스트 교체, 구형 undo 초기화, 시작 옵션 `+n` 줄 오프셋 적용, 버퍼(`saved_point`, `mark`) 및 활성 창(`point`, `top`) 경계 스냅을 원자적으로 수행한다.
  - WAL 헤더에 버퍼의 줄 끝 방식(LF / CRLF)을 함께 기록하고 복구 시 그대로 복원한다. 헤더 형식이 다른 구형 WAL(`NEONWAL1`)과 알 수 없는 줄 끝 값은 복구하지 않는다.
  - **복구 경로는 하나다 (I-45)**: 파일 읽기가 새 버퍼를 만들 때 WAL을 찾는다. 시작 인자든 `C-x C-f`든 같다. 이미 방문 중인 경로와 거부된 큰 파일은 버퍼가 없으므로 찾지 않는다.
  - **쓸 수 없는 WAL은 지우지 않는다 (I-44)**: 디스크 상태가 다르거나 손상된 WAL은 `.<원본이름>.wal.stale`로 옮기고(이전 stale 사본은 교체) `Stale WAL kept as <이름>`을 알린다. 옮기지 못하면 `Stale WAL for <이름> not kept: <오류>`. 옮김은 다음 유휴 기록보다 먼저 일어난다. 편집기는 `.stale` 파일을 지우지 않는다.
  - **scratch 보호 (I-42, I-43)**: 파일 없는 `*scratch*` 버퍼(`Backing::Scratch`)도 유휴 1초 뒤 `$XDG_STATE_HOME/neonemacs/scratch.wal`(미설정 시 `~/.local/state/neonemacs/scratch.wal`)에 기록한다. 시작 시 유효한 슬롯은 파일을 열기 전에 복구하고 `[Recovered *scratch* from WAL]`을 알린다. 쓸 수 없는 슬롯은 `scratch.wal.stale`로 옮긴다. scratch가 수정되지 않은 상태가 되거나(undo, 닫기) 종료하면 슬롯을 지운다. 종료는 `y` 확인을 거친 명시적 폐기다. 크래시만 슬롯을 남긴다.

## 8. 파일 입출력과 안전

- 열기(`C-x C-f`), 저장(`C-x C-s`), 다시 읽기(`revert-buffer`), 다른 이름으로 저장(`write-file`)을 지원한다.
- **원자적 저장**: 격리된 임시 파일에 기록 후 디스크 동기화를 거쳐 원자적으로 교체한다.
- **다른 이름으로 저장 (`write-file`)**: 쓰기가 성공한 뒤에만 연결 파일 경로를 새 경로로 바꾸고, 이전 경로의 잔여 WAL을 삭제한다. 쓰기가 실패하면 버퍼 이름, 경로, WAL을 그대로 둔다. 다른 버퍼가 이미 방문 중인 경로로는 저장하지 않고 `Buffer X is visiting <path>` 메시지를 띄운다. 방문하지 않은 기존 파일 위에 쓰려면 먼저 `File <path> exists; overwrite? (y or n)`로 묻고, `n`이면 아무것도 쓰지 않는다.
- **외부 변경 확인**: 저장은 읽은 뒤 디스크 상태가 달라졌으면 묻는다. 없는 경로로 연 뒤 외부에서 파일이 생긴 경우도 변경으로 본다. 새 파일의 첫 저장은 묻지 않는다.
- **WAL 쓰기 실패**: 유휴 WAL 쓰기가 실패하면 `WAL write failed: <path>: <error>`(여러 개면 `(+N more)`)를 띄우고 1초 뒤 다시 시도한다. 예/아니오 질문 등 Normal 모드가 아닐 때는 질문이 가려지지 않도록 메시지를 띄우지 않지만 재시도는 계속한다.
- **삭제된 파일 다시 읽기**: 디스크에서 사라진 파일은 `Revert failed: <path> does not exist`를 띄우고 버퍼와 WAL을 그대로 둔다.
- **경로 동일성**: 상대 경로는 작업 디렉터리 기준의 절대 경로로 바꿔 비교한다. 이 변환은 어휘적이다. `.`은 빼고 `..`은 바로 앞 구성요소와 접는다(상대 경로 맨 앞의 `..`만 남는다). 작업 디렉터리가 비어 있으면(테스트) 상대 경로를 그대로 두며, 심볼릭 링크는 따라가지 않는다. 한 파일은 최대 하나의 버퍼가 방문한다. 같은 파일을 여러 번 열면 기존 버퍼를 쓴다 (`neonemacs a.txt ./a.txt`는 버퍼 하나).
- **읽기**: UTF-8로 읽되, 디코딩 불가능한 바이트는 1바이트 Latin-1(`Unit::Raw`)로 보존해 데이터 손실 없이 편집·저장한다.
- **줄 끝 방식 (LF / CRLF)**: 파일을 열 때 `\r\n` 쌍과 단독 `\n` 개수의 다수결로 결정한다.
  - 메모리에는 `\n`만 유지하며(단독 `\r`은 보존), 저장 시에만 CRLF 버퍼의 `\n` 앞에 `\r`을 복원한다.
  - `toggle-eol`로 버퍼의 줄 끝 방식을 전환한다 (`LF <-> CRLF`). 되돌리기(`C-/`)로 취소할 수 있고, 미저장 변경으로 표시되어 WAL에 기록된다.
- **큰 파일**: `max-file-size`를 넘는 파일은 열지 않는다. `C-x C-f`는 `File too large: N bytes (max-file-size M)` 메시지만 띄우고 버퍼를 만들지 않는다. 다시 읽기는 버퍼와 WAL을 그대로 둔다. 잘린 앞부분만 열어 저장하는 경로는 없다.
- **외부 변경**: 열 때 기록한 디스크 상태 `(mtime, size)`가 현재 디스크와 다르면 저장 전 덮어쓸지 묻는다. 본 편집기가 방금 저장한 결과이거나 이전 상태를 알 수 없는 새 파일은 묻지 않고 저장한다.
- **종료 (`C-x C-c`)**: 미저장 변경 버퍼가 있으면 이름을 앞에서 3개까지(나머지는 `+N`) 보여 주며 `Modified: a, b, c +2; quit anyway? (y or n)`로 확인한다.
- **예/아니오 질문 (I-46)**: `y`(`Y`, 기본 번들 별칭 `ㅛ`)는 실행하고 `n`(`N`, 기본 번들 별칭 `ㅜ`), `C-g`, `Esc`는 `Quit`으로 취소한다. 별칭은 12절 `key_alias`로 바꾼다. 다른 키는 `Please answer y or n. <질문>`으로 질문을 반복하고 상태를 바꾸지 않는다. 프롬프트와 증분 검색도 `Esc`를 `C-g`처럼 취소로 받는다. Normal 모드의 `Esc`는 `M-` 접두다.
- **파일 잠금 없음**: `.lock` 파일을 만들지 않으며 저장 직전 디스크 상태 비교만으로 충돌을 감지한다.

## 9. 검색과 치환

- 기본은 문자열 증분 검색(`C-s`)이며, 뒤로 검색(`isearch-backward`)과 치환(`query-replace`)은 `M-x`로 호출한다.
- 정규식 검색/치환은 `isearch-forward-regexp`, `isearch-backward-regexp`, `query-replace-regexp`로 호출한다. 대소문자 구분은 `case-fold-search`(기본 `true`)를 따른다.
- 정규식 문법: `.`, `[...]`, `[^...]`, `*`, `^`, `$`. 매칭은 한 줄 안에서만 수행하며, 빈 매치에서도 무한 루프 없이 전진한다.
- `query-replace`는 치환 세션 전체가 한 번의 되돌리기 단위다. `C-g`(또는 `q`, `Esc`)로 중단하면 그때까지의 치환은 남는다. 보기 전용 버퍼에서는 시작하지 않고 `Buffer is read-only`를 띄운다.
- 치환은 커서 위치부터 앞으로만 찾는다. 시작 메시지가 `Query replacing from point (y, n, !, q)`로 이를 밝힌다. 응답 키는 `y`/SPC, `n`/DEL, `!`, `q`/RET이며 대문자와 기본 번들 별칭 `ㅛ`·`ㅜ`·`ㅂ`도 받는다. 그 밖의 키는 `Answer y, n, !, or q`를 띄우고 세션을 유지한다 (I-46).

## 10. 보기 전용

- 모드 시스템은 없으며 버퍼마다 보기 전용 플래그(`view_only`)를 둔다.
- 켜면 텍스트 편집, `toggle-eol`, `query-replace`를 거부한다. `view-mode`로 토글하며 상태 줄에 표시한다. view-mode를 여는 시작 옵션은 없다.

## 11. 한글과 UTF-8

- 읽기: UTF-8(비정상 바이트는 `Unit::Raw` 보존). 저장: 원본 바이트와 입력된 UTF-8 문자를 손실 없이 기록한다.
- 커서는 문자 경계를 따라 움직이며 멀티바이트 문자 중간에 멈추지 않는다.
- 표시 폭 (`src/core/width.rs`):
  - 탭: 다음 탭 스톱까지(`tab_width - col % tab_width`)
  - 제어 문자(0x00~0x1F, 0x7F): 2칸, C1 제어 문자(0x80~0x9F): 3칸
  - 한글, CJK 등 전각(East Asian Wide/Fullwidth) 문자: 2칸
  - 결합 문자(Mn, Me), 한글 자모 중성·종성(U+1160~11FF), ZWJ(U+200B~200D), 이모지 변형 선택자(U+FE00~FE0F): 0칸
  - 그 밖의 문자: 1칸

## 12. 확장과 설정 (Lua)

- 설정 파일 경로는 `$XDG_CONFIG_HOME/neonemacs/init.lua`이며, 미설정 시 `~/.config/neonemacs/init.lua`다 (세 플랫폼 공통).
- **최소 공개 API**:
  - `bind(keys, command)` / `unbind(keys)`: 키 바인딩 등록 및 제거 (단일 키 또는 `C-x` 2키 시퀀스만 허용)
  - `command(name, function)`: 사용자 명령 등록 (내장 명령 재정의 불가)
  - `run(name)`: 내장 또는 Lua 명령 실행 (최대 재귀 깊이 50)
  - `get(name)` / `set(name, value)`: 설정 조회 및 변경. 이름, 값, 기본값은 아래 "설정 가능 범위"의 표를 따른다. 알 수 없는 이름, 틀린 타입, 범위 밖의 값은 Lua 오류이며 설정은 바뀌지 않는다.
  - `key_alias(from, to)` / `key_unalias(from)`: 자판 별칭 등록 및 제거 (`from`은 한 글자, `to`는 ASCII 그래픽 문자 한 글자, 위반 시 Lua 오류, 없는 별칭 제거는 무동작). 질문 응답과, 정확히 일치하는 바인딩이 없는 접두·수정 키의 바인딩 조회(3절)에 적용된다. 일반 글자 입력, 프롬프트 입력, 검색어에는 적용하지 않는다.
  - `message(text)`: 에코 영역 메시지 표시
  - `syntax.register(name, spec)`: 구문 강조 규칙 등록
    - `extensions`: 확장자 배열 (선택, `filenames`와 합산 최소 1개 필수)
    - `filenames`: 전체 파일명 배열 (선택, 매칭 시 확장자보다 우선)
    - `line_comment`: 한 줄 주석 기호 (선택)
    - `keywords` / `types`: 예약어(Cyan) 및 타입(Magenta) 배열 (선택)
    - `case_insensitive`: 대소문자 무시 플래그 (선택, 기본 `false`)
    - `heading`: 제목 접두사 문자열 (선택, 빈 문자열 불가). 이 접두사로 시작하는 줄 전체를 예약어 색으로 칠하고 다른 강조는 하지 않는다. 번들 Markdown 정의가 `heading = "#"`를 쓴다
  - `buffer`: 활성 버퍼 조작 모듈 (0-기반 바이트 오프셋, 모든 변이·커서·마크 API는 문자 경계로 자동 스냅하며 비정상 UTF-8 바이트열도 런타임 오류 없이 바이트열 그대로 처리)
    - `buffer.point()` / `buffer.set_point(pos)`: 커서 오프셋 조회 및 이동
    - `buffer.len()`: 전체 바이트 길이
    - `buffer.get_text([start, end])`: 구간 바이트열 반환
    - `buffer.line_start(pos)` / `buffer.line_end(pos)`: 해당 위치의 줄 시작·끝 오프셋 반환
    - `buffer.width(text)`: 문자열 표시 열 폭 계산
    - `buffer.insert(pos, text)` / `buffer.delete(start, end)`: 삽입 및 삭제
    - `buffer.replace(start, end, text)`: 구간 삭제 후 삽입
    - `buffer.kill(start, end)`: 구간 삭제 후 킬 링에 추가
    - `buffer.mark()` / `buffer.set_mark(pos)`: 마크 조회 및 설정(`nil`이면 해제)
    - `buffer.comment_prefix()`: 활성 버퍼 파일명에 매칭되는 한 줄 주석 기호 조회
- **기본 번들 스크립트**:
  - 구문 강조(`syntax.lua`: Rust, C/C++, Python, JavaScript/TypeScript, Lua, Go, Shell, Makefile, SQL, TOML, JSON, YAML, Markdown), 파레토 텍스트 편집 명령(`text.lua`), 확장 키맵(`keymap.lua`: `C-k`, `C-x 2`, `C-x 3`, `C-x 1`, `C-x o`, `C-x b`, `C-x k`, `C-x C-w`, `C-x C-q`, `C-x h`, `C-x u`, `M-y`, `M-q`, `M-d`, `M-DEL`, `M-;`, `C-r`, `M-%`, `M-g`, `M-<`, `M->`, `C-l`, `M-!`)과 두벌식 자판 별칭(자모 26자와 Shift 자모 7자를 QWERTY 키로, 예: `ㅛ`→`y`, `ㅜ`→`n`, `ㅂ`→`q`, `ㅠ`→`b`)을 바이너리에 내장한다.
  - 내장 스크립트는 `init.lua` 전에 실행되며, `init.lua`에서 재정의하거나 해제할 수 있다.
- 다중 버퍼 임의 접근, 이벤트 훅, 직접 파일 I/O는 공개하지 않는다.
- **Lua 표준 라이브러리**: 기본 함수와 `string`, `table`, `math`, `utf8`만 쓸 수 있다. `io`, `os`, `package`, `require`, `coroutine`, `debug`, `dofile`, `loadfile`은 없다 (I-57). `print`는 화면 뒤의 터미널에 쓰므로 `message`를 쓴다.

### `init.lua` 적용과 다시 읽기

- **전부 또는 전무 (I-54)**: `init.lua`는 끝까지 오류 없이 실행됐을 때만 적용된다. 문법 오류든 실행 중 오류든, 오류가 나면 그 앞의 `set`, `bind`, `command`도 남지 않고 번들 스크립트만 적용된 상태로 시작한다. `init.lua`가 `run`으로 일으킨 편집기 밖의 결과(예: 파일 저장)는 되돌리지 않는다.
- **있는 파일이 적용되지 않으면 반드시 알린다 (I-55)**: 파일이 없으면 알리지 않는다. 파일이 있지만 읽을 수 없거나(권한, 디렉터리) UTF-8이 아니면(예: CP949) 오류로 알린다.
- **오류 기록**: 오류 전문은 `*init-log*` 버퍼에 남는다 (파일 없음, 수정 표시 없음, 화면에 자동으로 띄우지 않음). `switch-to-buffer`로 연다. 같은 이름의 파일을 방문하는 버퍼가 있어도 `*init-log*`와 `*Shell Command Output*`로 취급하지 않으며, `switch-to-buffer`와 `kill-buffer`는 파일 없는 쪽을 고른다. 에코 영역에는 `init.lua: <오류 첫 줄>`을 보이며, Lua 오류의 첫 줄에는 `init.lua:<줄 번호>:`가 들어 있다.
- **`reload-init`**: 편집기를 끄지 않고 `init.lua`를 다시 읽는다 (I-58).

  | 결과 | 설정과 Lua 명령 | 에코 영역 |
  | --- | --- | --- |
  | 성공 | 번들 스크립트 + 새 `init.lua`로 교체 | `Loaded init.lua` |
  | 파일 없음 | 번들 스크립트만으로 교체 | `No init.lua` |
  | 읽기 실패 또는 Lua 오류 | 이전 그대로 | `init.lua: <오류 첫 줄>` |
  | Lua 명령 안에서 `run("reload-init")` | 이전 그대로 | `reload-init: not available from Lua` |

  - 교체는 새로 시작한 것과 같다. 새 파일이 다시 만들지 않은 설정, 키, 별칭, 구문 정의, Lua 명령, Lua 전역 변수는 사라진다.
  - 버퍼, 창, 킬 링, 되돌리기 기록은 그대로다. 다시 읽을 때 `init.lua`가 한 버퍼 편집, `message`, 종료 요청은 반영하지 않는다.
  - 성공하거나 파일이 없으면 `*init-log*`를 비운다.

### 설정 가능 범위

패닉룸을 뺀 모든 기능은 `init.lua`로 켜고 끄고 바꿀 수 있다 (I-52, I-53). 범위는 다음과 같이 나뉜다.

#### 1. `get` / `set`으로 바꾸는 설정 (`set`은 값을 검사하고, 실패하면 아무것도 바꾸지 않는다)

| 이름 | 값 | 기본값 | 효과 |
| --- | --- | --- | --- |
| `fill-column` | 정수 1~65535 | 70 | `fill-paragraph` 폭 |
| `tab-width` | 정수 1~16 | 8 | 탭 칸 수 |
| `expand-tabs` | 불리언 | `false` | TAB이 공백을 넣는다 |

#### 2. 다른 API로 바꾸는 것

- 키: `bind` / `unbind`. 명령을 끄려면 그 키를 `unbind`한다. 명령은 `M-x`에 남는다. 내장 명령 이름은 재정의할 수 없다.
- 입력 배열: `key_alias` / `key_unalias`.
- 언어 규칙과 제목 강조: `syntax.register`.
- 번들 Lua 명령(`text.lua`의 `comment-dwim`, `fill-paragraph` 등): `command`로 같은 이름을 다시 등록한다.

#### 3. 패닉룸: 설정으로 끌 수 없는 안전망

설정 키, Lua 함수, 키 해제 어느 것으로도 끌 수 없다 (I-53). 키 바인딩은 바꿀 수 있지만 동작 자체는 남는다. `C-g`는 키맵 조회 전에 처리되므로 `unbind`로도 지울 수 없다.

- 터미널 복원 (13절).
- WAL 기록과 복구, WAL 위치와 지연, scratch 영속 (7절).
- 저장 시 외부 변경 검사, 덮어쓰기·종료·버퍼 닫기·다시 읽기 확인 (8절).
- `C-g`와 `Esc` 취소 (3절, 9절, I-46).

#### 4. 고정된 내부 한계 (사용자 선호가 아니라 구현 규약이다)

WAL 형식, `run` 재귀 깊이 50, 이벤트 폴링 간격, 한 번에 하나의 셸 명령, 제어 문자 표기, 바인딩 깊이(I-12), 화면 배치(상태 줄과 에코 영역 높이), 종료 확인에 보이는 버퍼 이름 수.

#### 5. 새 기능 후보 (미구현. 값만 노출하는 설정이거나 대안 동작이 없다)

- 값만 바꾸는 것: 구문 색(`face-*`), 줄 잘림 표시 문자, 스피너 글자.
- 대안 동작이 없는 것: `scroll-margin`, smart-case 검색, 줄 감싸기, 치환 시 대소문자 보존, `find-file` 경로 완성, PgUp/Delete/F 키 바인딩, 상태 줄 형식, 단어 문자 정의.

### 시작 방식 (`src/shell/startup/`)

- 모든 파일 인자를 백그라운드 버퍼로 열고 첫 번째 파일을 화면에 표시한다.
- 인자는 앞에서부터 한 번에 해석한다(`parse_args` → `Invocation`).
  - `+n`(바로 뒤 파일 인자를 `n`번째 줄에서 열기)은 `n`이 1 이상의 정수가 아니거나 뒤에 파일 인자가 없으면 오류다.
  - `-v`, `--version`은 `neonemacs 0.1.0`을 표준 출력에 쓰고 종료 코드 `0`으로 종료한다.
  - `-h`, `--help`는 사용법을 표준 출력에 쓰고 종료 코드 `0`으로 종료한다.
  - `-v`와 `-h`는 편집기를 시작하지 않으므로 `init.lua` 실행, WAL 복구, 터미널 원시 모드 설정을 수행하지 않는다. 먼저 나온 쪽이 이기며, 그 앞의 `+n` 오류가 있으면 오류가 우선한다.
  - `--` 이후의 인자는 `-`로 시작해도 파일로 취급한다. `+n` 규칙은 그대로 적용된다.
  - 그 밖의 `-`로 시작하는 인자(단독 `-` 포함)는 `unknown option: <인자>`를 출력하고 종료 코드 `2`로 종료한다.
- 파일마다 `open`과 같은 경로로 열고(7절, I-45) 유효한 미저장 WAL이 있으면 자동 복구(`restore_buffer_content`)한다. 알림(`[Recovered NAME from WAL]`, `Stale WAL kept as ...`, `File too large ...`, `Cannot open ...`)은 알림이 있는 파일마다 하나씩 표시한다.
- scratch 슬롯은 파일을 열기 전에 복구한다 (7절).
- `init.lua`를 읽지 못하거나 실행 중 오류가 나도 프로세스를 중단하지 않는다. 번들 스크립트만 적용하고 위 "`init.lua` 적용과 다시 읽기"대로 알린다.
- 시작 알림은 서로를 대체하지 않는다 (I-56). `init.lua` 오류, scratch 복구 알림, 파일 알림을 이 순서로 `; `로 이어 표시한다.
- `*scratch*`는 `init.lua`가 정한 `default-eol`로 시작한다. `init.lua`가 `*scratch*`를 편집했으면(예: `run("toggle-eol")`) 그 편집이 남긴 줄 끝 방식을 유지한다. WAL에서 복구한 scratch는 기록된 줄 끝 방식을 따른다.

## 13. 플랫폼

- Linux, macOS, Windows를 지원하며 생존 집합 키는 동일하게 동작한다.
- **터미널 수명주기와 안전한 복원 (`TerminalGuard`)**:
  - 원시 모드와 대체 화면은 정상 종료, 조기 오류 반환, 패닉 발생 시(표준 패닉 메시지 출력 전 선행 복원) 모두 원래 상태로 복원된다.
- 치명적 런타임 오류는 메시지를 출력하고 종료 코드 `1`로 종료한다.

## 14. 동작 원칙

1. **단순함과 이식성을 우선한다.** 기능보다 크기와 이식성을 지킨다.
2. **인지 부하를 줄인다.** 키는 최소로 두고 나머지는 익숙한 Emacs 명령 이름으로 `M-x`에서 호출한다.
3. **입력에 지연이 없어야 한다.**
4. **저장 전에 묻는다.** 외부 변경, 미저장 종료는 먼저 확인한다. 큰 파일은 열지 않아 부분 저장이 일어나지 않는다.
5. **판단할 수 없으면 막지 않는다.** 이전 상태를 알 수 없는 파일은 차단하지 않고 저장한다.
6. **저장 사고를 막는다.** 저장 전 편집은 WAL로 보호한다.

## 15. 한계와 주의점

- Emacs 매크로 문법과 호환되지 않으며, 키 호환은 3절(생존 집합)과 기본 번들 키맵 범위에서 보장한다.
- `C-/`는 많은 터미널에서 `C-_`로 전송되므로 두 키를 함께 바인딩한다.
- 한글 IME 조합 표시는 터미널 구현에 따른다.
- 같은 파일이나 같은 상태 디렉터리를 쓰는 편집기를 둘 이상 실행하면 WAL과 scratch 슬롯을 서로 덮어쓸 수 있다. 잠금이 없으므로 막지 않는다 (8절).
- 기본 자판 별칭은 두벌식뿐이다. 다른 입력 배열은 `init.lua`에서 `key_alias`로 추가한다. 별칭은 질문 응답과 접두·수정 키의 바인딩 조회에만 적용되고, 일반 입력(self-insert), 프롬프트 입력, 검색어에는 적용되지 않는다 (I-48). 바인딩 조회는 정확히 일치하는 글자만 보므로 대소문자가 있는 배열은 두 형태를 모두 등록해야 한다.
- `reload-init`으로 바꾼 `default-eol`은 그 뒤에 만드는 버퍼에만 적용된다. 이미 있는 `*scratch*`의 줄 끝 방식은 바뀌지 않는다.
- Lua 명령이 실행 중에 낸 오류는 에코 영역에 첫 줄만 보이고 `*init-log*`에는 남지 않는다.
- 터미널과 입력기에 따라 한글 상태의 `Alt`+자모가 다른 값으로 전달될 수 있다. 그 경우 `Esc` 뒤 자모나 영문 전환을 쓴다.
