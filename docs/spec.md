# neonemacs 기능 명세

> 독자: 사용자와 구현자

## 1. 정체성

- Emacs 키 감각을 가진 경량 터미널 편집기다.
- Emacs 구현의 코드, 형식, 매크로 문법과 호환하지 않는다. 키와 명령 이름은 Emacs 관례를 따른다.
- 목표: 가볍고, 저장 사고가 없고, UTF-8과 한글을 정확히 다룬다.
- 키는 생존 집합만 두고, 나머지는 `M-x`로 호출하거나 Lua 설정으로 확장한다 (3절, 4절, 12절).

## 2. 구현 기준

- **언어**: Rust.
- **아키텍처**: 함수형 코어 / 명령형 쉘 (Functional Core, Imperative Shell).
  - **코어**: I/O 부수효과를 일절 포함하지 않는 순수 상태 전이 기계다. 모든 함수 시그니처에서 가변 참조(`&mut`)를 배제하고 값 전달로만 상태를 전이하며, 버퍼 갱신 시 소유권 이동을 통해 대규모 파일에서도 입력 지연을 방지한다.
  - **쉘**: 터미널, 파일 시스템, 백그라운드 프로세스, Lua 런타임 등 외부 부수효과를 전담한다. 코어가 발행하는 모든 효과 요청을 쉘이 실행하고 단일 이벤트로 응답한다.
- **확장**: Lua 임베딩. Emacs 매크로 문법은 지원하지 않는다.
- **플랫폼**: Linux, macOS, Windows.
- **바이너리**: 릴리스·strip 기준 5MB 이하 (Linux x86_64).

## 3. 키 체계

- 키는 아래 표만 제공한다. 나머지 기능은 `M-x`로 호출하거나 번들 키맵으로 확장한다 (4절, 12절). 키 호환은 이 범위에서만 보장한다.
- 터미널 흐름 제어(XON/XOFF)는 끈다. 그래야 `C-s`를 쓸 수 있다.

| 기능 | 키 |
| --- | --- |
| 파일 열기 | `C-x C-f` |
| 저장 | `C-x C-s` |
| 종료 (미저장 변경이 있으면 확인) | `C-x C-c` |
| 이동 | `C-f` `C-b` `C-n` `C-p`, `C-a` `C-e`, 방향키 |
| 삭제 | Backspace, `C-d` |
| 마크 (영역 시작) | `C-SPC` |
| 잘라내기 / 복사 / 붙여넣기 | `C-w` / `M-w` / `C-y` |
| 실행 취소 | `C-/`, `C-_` |
| 앞으로 증분 검색 | `C-s` |
| 명령 실행 | `M-x` |
| 취소 | `C-g` |

## 4. 명령 실행 (M-x)

- 명령 이름을 입력하는 동안 자동완성을 보여 준다. 내장 명령과 Lua 등록 명령이 알파벳순으로 통합 정렬되어 연결된 키를 함께 표시하고, 키가 없으면 비워 둔다.
- 명령 이름은 Emacs 이름을 따른다. Emacs에 없는 고유 명령은 `동사-대상` 형식으로 정한다.
- 기본 명령 목록은 아래와 같다.

| 기능 | 명령 이름 |
| --- | --- |
| 뒤로 검색 | `isearch-backward` |
| 정규식 앞으로 / 뒤로 검색 | `isearch-forward-regexp` / `isearch-backward-regexp` (9절) |
| 치환 (확인하며 바꾸기) | `query-replace` |
| 정규식 치환 | `query-replace-regexp` (9절) |
| 줄 번호로 이동 | `goto-line` |
| 버퍼 전환 / 닫기 | `switch-to-buffer` / `kill-buffer` |
| 창 나누기 (위아래 / 좌우) | `split-window-below` / `split-window-right` |
| 나머지 창 닫기 / 다음 창 | `delete-other-windows` / `other-window` |
| 줄 끝까지 잘라내기 | `kill-line` |
| 문단 다시 채우기 | `fill-paragraph` |
| 다른 이름으로 저장 | `write-file` |
| 다시 읽기 | `revert-buffer` |
| 줄 끝 방식 전환 (LF / CRLF) | `toggle-eol` (8절) |
| 커서와 마크 위치 교환 | `exchange-point-and-mark` |
| 셸 명령 실행 | `shell-command` |
| 잘라낸 텍스트 순환 | `yank-pop` |
| 실행 취소 (키 없이) | `undo` |
| 보기 전용 켜기 / 끄기 | `view-mode` (10절) |

- **비동기 셸 명령 (`shell-command`)**: 백그라운드로 실행되어 터미널 UI를 차단하지 않는다.
  - 실행 중에는 에코 영역에 회전 스피너(`[Running... |]`)가 표시된다.
  - 이미 명령이 실행 중일 때 추가 실행은 차단 안내와 함께 중복 생성을 막는다.
  - 프롬프트나 증분 검색 진입 중에는 사용자 입력을 방해하지 않도록 스피너 갱신을 유예하며, 완료 결과는 안전하게 반영된다.
  - 실행 스레드가 비정상 종료되어도 에코 영역이 고착되지 않고 오류를 즉시 보고한다.

## 5. 화면과 창

- 여러 버퍼를 동시에 연다. 버퍼마다 커서 위치와 마크를 따로 기억한다.
- 창을 나누면 같은 버퍼를 두 곳에서 볼 수 있다. 창마다 커서가 독립적이다.
- 버퍼 전환과 창 나누기는 `M-x` 또는 단축키로 접근한다.
- **버퍼와 창 생존 불변식**: 최소 1개의 버퍼가 항상 존재한다. 마지막 버퍼를 닫으면 자동으로 빈 `*scratch*` 버퍼가 생성된다. 모든 창은 항상 살아 있는 버퍼만을 참조하며, 특정 버퍼를 닫을 때 해당 버퍼를 보던 모든 창은 다른 살아 있는 버퍼로 즉시 안전하게 전환된다.
- 상태 줄에 파일 이름, 상태(변경됨, 보기 전용), 줄 끝 방식(LF, CRLF), 위치 백분율을 보여 준다. 폭이 모자라면 줄 끝 방식부터 생략한다.
- **경량 구문 강조**: 주요 프로그래밍 언어의 키워드, 문자열, 주석, 숫자를 선형 탐색하여 ANSI 색상으로 표시한다. 전각 문자(한글·CJK) 표시 폭을 반영하여 화면 셀과 커서 위치를 정확히 유지하며, 스타일이 변경된 행만 감지하여 화면을 차등 갱신한다.
- **대용량 파일 탐색 성능**: 개행 탐색 최적화로 수십 MB 대용량 파일에서도 입력 지연과 화면 갱신 지연이 없다.
- 입력에 지연이 없어야 한다. 느린 원격 연결에서도 화면 갱신이 실용적인 속도로 끝나야 한다.
- 터미널 크기가 바뀌면 화면을 새 크기에 맞춰 다시 배치한다.

## 6. 편집

- 삽입이 기본이자 유일한 입력 방식이다. 덮어쓰기 모드는 없다.
- `C-SPC`로 마크를 찍으면 마크와 커서 사이가 영역이다. `C-w`, `M-w`, `C-y`로 잘라내기, 복사, 붙여넣기를 한다. 잘라낸 텍스트 순환(`yank-pop`)은 `M-x`로 호출한다. 연속된 잘라내기는 하나의 킬 항목으로 병합된다.
- **파레토 핵심 텍스트 편집 명령**: 실사용 빈도가 높은 기본 텍스트 조작 명령을 제공한다.
  - 단어 이동 및 삭제: `forward-word`, `backward-word`, `kill-word`, `backward-kill-word`
  - 버퍼 양끝 이동: `beginning-of-buffer`, `end-of-buffer`
  - 문단 재정렬: `fill-paragraph` (설정된 `fill-column` 너비에 맞춤)
  - 주석 토글: `comment-dwim` (언어별 주석 기호 감지 및 영역/단일행 토글)
  - 전체 선택: `mark-whole-buffer`
- **커서 및 앵커 불변식**: 커서와 마크는 모든 이동과 편집 상태 전이에서 항상 버퍼 범위(0..=길이) 내의 유효한 문자 경계에만 놓인다. 다중 바이트 문자 중간이나 버퍼 범위를 벗어나는 커서 상태는 원천 배제된다.

## 7. 실행 취소 및 크래시 복구

- **메모리 내 undo**: 편집 단위로 되돌린다. 키는 `C-/`와 `C-_`다. 터미널이 둘 중 하나만 보내도 동작해야 한다.
- **Emacs 방식**: 다시 실행 키는 두지 않는다. 실행 취소를 다시 실행 취소하면 앞 상태로 돌아간다.
- **영속 undo**: 저장할 때 undo 기록을 원본 옆 `.<원본이름>.undo`에 남긴다. 다시 열면 기록을 읽어 되돌릴 수 있다. 기록이 원본과 맞지 않으면(수정 시각 또는 크기 불일치) 무시한다.
- **크래시 복구 (WAL)**: 실제 파일에 연결된 버퍼에 미저장 변경이 발생한 후 1초간 유휴 상태가 지속되면 백그라운드로 `.<원본이름>.wal`에 안전하게 영속화한다.
  - 디스크 동기화 후 원자적으로 교체하여 갑작스러운 정전 시에도 손상 파일이 남지 않는다.
  - WAL 파일은 원본 파일의 디스크 상태(수정 시각, 크기)를 검증하여, 비정상 종료 후 외부에서 원본이 변경되었으면 복구를 거부하고 외부 데이터를 보존한다.
  - 정상 저장, 다시 읽기, 버퍼 닫기, 다른 이름으로 저장, 또는 미저장 종료 확인 시 잔여 WAL 파일을 즉시 삭제한다.
  - WAL 복구 시 내용이 변경되더라도 커서 위치와 마크를 복원된 텍스트 경계로 자동 정규화한다.
  - WAL은 줄 끝 방식을 저장하지 않으며, 복구 시 디스크 파일의 방식을 따른다.

## 8. 파일 입출력과 안전

- 열기, 다시 읽기, 저장, 다른 이름으로 저장을 지원한다. 다시 읽기와 다른 이름으로 저장은 `M-x`로 호출한다 (`revert-buffer`, `write-file`).
- **원자적 저장**: 모든 디스크 저장은 격리된 임시 파일에 기록 후 디스크 동기화를 거쳐 원자적으로 교체된다.
- **다른 이름으로 저장 (`write-file`)**: 버퍼의 연결 파일 경로를 새 경로로 변경하고 저장하며, 이전 경로의 유휴 WAL은 즉시 정리한다.
- **읽기**: UTF-8로 읽는다. 잘못된 바이트는 1바이트 Latin-1 문자로 보존해 내용이 사라지지 않게 한다.
- **줄 끝 방식 (LF / CRLF)**: 버퍼마다 하나다 (`LF` 또는 `CRLF`). 파일을 열 때 `\r\n` 쌍과 `\n` 개수를 비교하는 다수결로 결정한다.
  - 버퍼 메모리 안에는 항상 `\n`만 둔다. 파일을 읽을 때 `\r\n`에서 `\r`을 제거하며, 단독 `\r`은 보존한다.
  - 저장할 때 CRLF 버퍼는 `\n` 앞에 `\r`을 붙이고, LF 버퍼는 그대로 쓴다.
  - 줄 끝 전환(`toggle-eol`): 버퍼의 줄 끝 방식을 뒤집는다 (`LF <-> CRLF`).
- **잘린 파일**: 크기 제한으로 잘린 파일은 저장할 때 확인받는다.
- **외부 변경**: 열 때 기록한 파일 상태가 디스크와 다르면 저장할 때 덮어쓸지 묻는다. 이 편집기가 방금 저장한 결과는 외부 변경이 아니다. 이전 상태를 확인할 수 없으면 변경으로 보지 않고 저장한다.
- **종료** (`C-x C-c`): 미저장 변경이 있으면 확인한다.
- **파일 잠금 없음**: 잠금 파일을 만들지 않으며 "File in use" 질문도 없다.

## 9. 검색과 치환

- 기본은 문자열 증분 검색이다. `C-s`로 앞으로 찾는다. 글자를 칠 때마다 이동하고, `C-s`를 다시 누르면 다음 일치로 간다.
- 뒤로 검색(`isearch-backward`)과 치환(`query-replace`)은 `M-x`로 호출한다.
- 대소문자 구분과 정규식은 명령으로 고른다 (`isearch-forward-regexp`, `isearch-backward-regexp`, `query-replace-regexp`). 대소문자는 설정 `case-fold-search`(기본 `true`)로 정한다.
- 정규식: `.`, `[...]`, `[^...]`, `*`, `^`, `$`. 일치는 한 줄 안에서만 한다.

## 10. 보기 전용

- 모드 시스템은 없다.
- **보기 전용 플래그**: 버퍼마다 하나다. 켜면 내용을 바꿀 수 없으며 `toggle-eol`도 거부한다. `view-mode`로 켜고 끄며 상태 줄에 표시한다.
- 시작 옵션 `-v`는 없다. 파일을 연 뒤 `view-mode`를 호출한다.

## 11. 한글과 UTF-8

- 읽기: UTF-8. 저장: 읽은 바이트는 그대로 저장하고, 입력 문자는 표준 형식으로 인코딩한다.
- 커서는 문자 경계를 따라 움직인다. 한 글자가 여러 바이트여도 중간에 멈추지 않는다.
- 표시 폭:
  - 탭은 다음 탭 위치까지 차지한다.
  - 제어 문자는 2칸, C1 제어 문자(0x80~0x9F)는 3칸이다.
  - 한글, CJK 등 전각(East Asian Wide/Fullwidth) 문자는 2칸이다.
  - 결합 문자(Mn, Me), 한글 자모 중성·종성(U+1160~11FF), ZWJ 등은 0칸이다.
  - 그 밖의 문자는 1칸이다.

## 12. 확장과 설정 (Lua)

- 설정과 확장은 Lua로 한다. 파일은 `~/.config/neonemacs/init.lua`이며, `XDG_CONFIG_HOME`이 있으면 `$XDG_CONFIG_HOME/neonemacs/init.lua`다. 세 플랫폼 모두 같은 규칙이다.
- **공개 API는 최소로 유지한다.**
  - `bind(keys, command)`: 키 바인딩 추가와 변경
  - `unbind(keys)`: 키 바인딩 제거
  - `command(name, function)`: 명령 등록
  - `run(name)`: 명령 실행
  - `get(name)` / `set(name, value)`: 설정 값 읽기와 쓰기
  - `message(text)`: 에코 영역에 메시지 표시
  - `syntax.register(name, spec)`: 구문 강조 규칙 등록 (확장자 목록, 주석 기호, 키워드 목록)
  - `buffer`: 활성 버퍼 텍스트 조작 모듈 (0-기반 UTF-8 오프셋)
    - `buffer.point()` / `buffer.set_point(pos)`: 커서 위치 조회 및 이동
    - `buffer.len()`: 전체 바이트 길이
    - `buffer.get_text([start, end])`: 지정 구간 문자열 반환
    - `buffer.line_start(pos)` / `buffer.line_end(pos)`: 라인 경계 오프셋 반환
    - `buffer.width(text)`: 표시 열 폭 계산
    - `buffer.insert(pos, text)` / `buffer.delete(start, end)`: 텍스트 삽입 및 삭제
    - `buffer.replace(start, end, text)`: 원자적 텍스트 치환
    - `buffer.kill(start, end)`: 텍스트 삭제 후 킬 링 푸시
    - `buffer.mark()` / `buffer.set_mark(pos)`: 마크 오프셋 조회 및 설정/해제
    - `buffer.comment_prefix()`: 활성 버퍼의 한 줄 주석 기호 조회
- **기본 번들 스크립트**:
  - 기본 구문 강조(`syntax.lua`), 파레토 핵심 텍스트 편집 명령(`text.lua`), 표준 확장 키맵(`keymap.lua`: `C-k`, `C-x 2`, `C-x 3`, `C-x 1`, `C-x o`, `C-x b`, `C-x k`, `C-x C-w`, `C-x C-q`, `C-x h`, `C-x u`, `M-y`, `M-q`, `M-d`, `M-DEL`, `M-;`, `C-r`, `M-%`, `M-g`, `M-f`, `M-b`, `M-<`, `M->`, `M-!`)은 바이너리 내장 스크립트로 제공된다.
  - 내장 스크립트는 `init.lua` 실행 전에 부트스트랩되며, 사용자 설정에서 자유롭게 재정의하거나 해제할 수 있다.
- 다중 버퍼 임의 접근, 이벤트 훅, 파일 시스템 직접 I/O는 공개하지 않는다.

### 시작 방식

- 파일 인자는 모두 백그라운드 버퍼로 열고, 첫 번째 파일을 화면에 보인다.
- 유일한 시작 옵션은 `+n`(n번째 줄에서 열기)이다. `+n`은 바로 뒤에 오는 파일 인자에 적용된다.
  - `n`은 1 이상의 정수여야 하며, 유효하지 않으면 오류 메시지를 출력하고 종료 코드 `2`로 종료한다.
- 시작 시 각 파일에 유효한 미저장 WAL이 존재하면 자동으로 복구하며 복구 알림을 표시한다.
- `init.lua`가 있으면 시작할 때 자동 실행하며, 스크립트 오류 발생 시에도 프로세스가 중단되지 않고 에코 영역에 안내를 남긴다.

## 13. 플랫폼

- Linux, macOS, Windows를 지원한다.
- 생존 집합 키는 세 플랫폼 모두에서 동일하게 동작한다.
- **터미널 수명주기와 안전한 복원**:
  - 터미널 원시 모드와 대체 화면은 안전하게 관리되어, 정상 종료뿐만 아니라 조기 오류 반환 시에도 원래 상태로 복원된다.
  - 패닉 발생 시 표준 패닉 메시지가 출력되기 전에 터미널 화면과 원시 모드를 선행 복원하여 셸 환경 파손을 방지한다.
- 치명적인 런타임 오류는 메시지를 남기고 종료 코드 `1`로 종료한다.

## 14. 동작 원칙

1. **단순함과 이식성을 우선한다.** 기능보다 크기와 이식성을 지킨다.
2. **인지 부하를 줄인다.** 키는 적게 두고, 나머지는 익숙한 Emacs 명령 이름으로 `M-x`에서 부른다. 새 규칙은 Emacs에 없을 때만 도입한다.
3. **입력에 지연이 없어야 한다.**
4. **저장 전에 묻는다.** 잘린 파일, 외부 변경, 미저장 종료는 먼저 묻는다.
5. **판단할 수 없으면 막지 않는다.** 이전 상태를 알 수 없는 파일은 차단하지 않고 저장한다.
6. **저장 사고를 막는다.** 저장 전 편집 기록은 영속 undo로 남긴다.

## 15. 한계와 주의점

- Emacs와 독립된 편집기다. Emacs 구현의 매크로 문법과 호환되지 않는다.
- 키 호환은 3절(생존 집합) 및 기본 번들 키맵 범위에서 보장한다.
- `C-/`는 많은 터미널에서 `C-_`로 전송되므로 두 키를 함께 바인딩한다.
- 영속 undo는 저장된 이력만 보존하며, 미저장 편집은 WAL(7절)이 복구한다.
- `toggle-eol`은 undo와 WAL에 기록되지 않는다. 비정상 종료 후에는 디스크 파일의 줄 끝 방식으로 돌아간다.
- 한글 IME 조합 표시는 터미널에 따라 다르다.
