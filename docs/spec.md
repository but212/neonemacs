# neonemacs 기능 명세

> 독자: 사용자와 구현자

## 1. 정체성

- Emacs 키 감각을 가진 경량 터미널 편집기다.
- Emacs 구현의 코드, 형식, 매크로 문법과 호환하지 않는다. 키와 명령 이름은 Emacs 관례를 따른다.
- 목표: 가볍고, 저장 사고가 없고, UTF-8과 한글을 정확히 다룬다.
- 키는 생존 집합만 두고, 나머지는 `M-x`로 호출한다 (3절, 4절).

## 2. 구현 기준

- **언어**: Rust.
- **확장**: Lua 임베딩. Emacs 매크로 문법은 지원하지 않는다.
- **플랫폼**: Linux, macOS, Windows.
- **바이너리**: 릴리스·strip 기준 5MB 이하 (Linux x86_64).

## 3. 키 체계

- 키는 아래 표만 제공한다. 나머지 기능은 `M-x`로 호출한다 (4절). 키 호환은 이 범위에서만 보장한다.
- 터미널 흐름 제어(XON/XOFF)는 끈다. 그래야 `C-s`를 쓸 수 있다.

| 기능 | 키 |
| --- | --- |
| 파일 열기 | `C-x C-f` |
| 저장 | `C-x C-s` |
| 종료 (미저장 변경이 있으면 확인) | `C-x C-c` |
| 이동 | `C-f` `C-b` `C-n` `C-p`, `C-a` `C-e`, 방향키 |
| 삭제 | Backspace, `C-d` |
| 마크 (영역 시작) | `C-SPC` |
| 잘라내기 / 복사 / 붙여넣기 | `C-w` / `M-w` / `C-y` |
| 실행 취소 | `C-/`, `C-_` |
| 앞으로 증분 검색 | `C-s` |
| 명령 실행 | `M-x` |
| 취소 | `C-g` |

## 4. 명령 실행 (M-x)

- 명령 이름을 입력하는 동안 자동완성을 보여 준다. 명령 목록에는 연결된 키를 함께 표시하고, 키가 없으면 비워 둔다.
- 명령 이름은 Emacs 이름을 따른다. Emacs에 없는 고유 명령은 `동사-대상` 형식으로 정한다.
- 내장 명령 테이블은 알파벳순으로 정렬되어 있으며, 이름으로 디스패치된다.
- 키가 없는 기능의 명령 이름은 아래와 같다.

| 기능 | 명령 이름 |
| --- | --- |
| 뒤로 검색 | `isearch-backward` |
| 정규식 앞으로 / 뒤로 검색 | `isearch-forward-regexp` / `isearch-backward-regexp` (9절) |
| 치환 (확인하며 바꾸기) | `query-replace` |
| 정규식 치환 | `query-replace-regexp` (9절) |
| 줄 번호로 이동 | `goto-line` |
| 버퍼 전환 / 닫기 | `switch-to-buffer` / `kill-buffer` |
| 창 나누기 (위아래 / 좌우) | `split-window-below` / `split-window-right` |
| 나머지 창 닫기 / 다음 창 | `delete-other-windows` / `other-window` |
| 줄 끝까지 잘라내기 | `kill-line` |
| 문단 다시 채우기 | `fill-paragraph` |
| 다른 이름으로 저장 | `write-file` |
| 다시 읽기 | `revert-buffer` |
| 커서와 마크 위치 교환 | `exchange-point-and-mark` |
| 셸 명령 실행 | `shell-command` |
| 잘라낸 텍스트 순환 | `yank-pop` |
| 실행 취소 (키 없이) | `undo` |
| 보기 전용 켜기 / 끄기 | `view-mode` (10절) |

- **비동기 셸 명령 (`shell-command`)**: 백그라운드 스레드로 실행되어 터미널 UI를 차단하지 않는다.
  - 실행 중에는 에코 영역에 회전 스피너(`[Running... |]`)가 표시된다.
  - 이미 명령이 실행 중일 때 추가 실행은 스피너와 함께 차단 안내(`A shell command is already running`)가 표시되며 중복 생성을 막는다.
  - 프롬프트(`M-x`, 파일 열기 등)나 증분 검색(`C-s`, `isearch`) 진입 중이거나 상태 알림 표시 중에는 사용자 입력을 방해하지 않도록 스피너 갱신을 유예하며, 완료 결과는 안전하게 반영된다.
  - 작업 스레드가 비정상 단절(패닉 등)되어도 에코 영역이 `[Running...]`에 고착되지 않고 비정상 종료 오류를 즉시 보고한다.

## 5. 화면과 창

- 여러 버퍼를 동시에 연다. 버퍼마다 커서 위치와 마크를 따로 기억한다.
- 창을 나누면 같은 버퍼를 두 곳에서 볼 수 있다. 창마다 커서가 독립적이다.
- 버퍼 전환과 창 나누기는 `M-x`로만 접근한다 (4절).
- **버퍼와 창 생존 불변식**: 최소 1개의 버퍼가 항상 존재한다. 마지막 버퍼를 닫으면 자동으로 빈 `*scratch*` 버퍼가 생성된다. 모든 창은 항상 살아 있는 버퍼만을 참조하며, 특정 버퍼를 닫을 때 해당 버퍼를 보던 모든 창은 다른 살아 있는 버퍼(또는 새로 생성된 `*scratch*`)로 즉시 안전하게 전환된다. 현재 선택된 창 인덱스는 항상 유효한 분할 창 범위 내로 제한된다.
- 상태 줄에 파일 이름, 상태(변경됨, 보기 전용), 위치 백분율을 보여 준다.
- **경량 구문 강조**: 주요 프로그래밍 언어(Rust, C, Python, JS, Lua, Go, Markdown)의 키워드, 문자열, 주석, 숫자를 1-pass로 토큰화하여 ANSI 색상으로 표시한다. 전각 문자(한글·CJK) 및 결합문자의 표시 폭을 반영하여 화면 격자 셀과 커서 위치를 유지하며, 텍스트뿐만 아니라 구문 강조 스타일만 변경된 행도 감지하여 화면을 차등 갱신한다.
- 입력에 지연이 없어야 한다. 느린 원격 연결에서도 화면 갱신이 실용적인 속도로 끝나야 한다.
- 터미널 크기가 바뀌면 화면을 새 크기에 맞춰 다시 배치한다.

## 6. 편집

- 삽입이 기본이자 유일한 입력 방식이다. 덮어쓰기 모드는 없다.
- `C-SPC`로 마크를 찍으면 마크와 커서 사이가 영역이다. `C-w`, `M-w`, `C-y`로 잘라내기, 복사, 붙여넣기를 한다. 잘라낸 텍스트 순환(`yank-pop`)은 `M-x`로 호출한다.
- 줄 끝까지 잘라내기(`kill-line`)와 문단 재정렬(`fill-paragraph`)은 `M-x`로 호출한다. 채움 열은 설정 값으로 지정한다.
- **커서 및 앵커 불변식**: 커서와 마크는 모든 이동과 편집 상태 전이에서 항상 버퍼 범위(0..=길이) 내의 유효한 문자 경계에만 놓인다. 다중 바이트 문자 중간이나 버퍼 범위를 벗어나는 커서 상태는 데이터 구조와 전이 생성자 수준에서 원천적으로 배제된다.

## 7. 실행 취소 및 크래시 복구

- **메모리 내 undo**: 편집 단위로 되돌린다. 키는 `C-/`와 `C-_`다. 터미널이 둘 중 하나만 보내도 동작해야 한다.
- **Emacs 방식**: 다시 실행 키는 두지 않는다. 실행 취소를 다시 실행 취소하면 앞 상태로 돌아간다.
- **영속 undo**: 저장할 때 undo 기록을 원본 옆 `.<원본이름>.undo`에 남긴다. 다시 열면 기록을 읽어 되돌릴 수 있다. 기록이 원본과 맞지 않으면(mtime 또는 크기 불일치) 무시한다.
- **크래시 복구 (WAL)**: 실제 파일에 연결된 버퍼에 미저장 변경이 발생한 후 1초간 유휴 상태가 지속되면 백그라운드로 `.<원본이름>.wal`에 안전하게 영속화한다. WAL 파일은 원본 파일의 디스크 상태(mtime, 크기)와 버전 스키마를 포함하여, 비정상 종료 후 재시작 시 원본이 외부에서 변경되지 않았을 때만 안전하게 복구된다. 정상 저장, 다시 읽기, 버퍼 닫기, 또는 미저장 종료 확인으로 변경이 해소되면 WAL 파일은 즉시 삭제된다.

## 8. 파일 입출력과 안전

- 열기, 다시 읽기, 저장, 다른 이름으로 저장을 지원한다. 다시 읽기와 다른 이름으로 저장은 `M-x`로 호출한다 (`revert-buffer`, `write-file`).
- **읽기**: UTF-8로 읽는다. 잘못된 바이트는 1바이트 Latin-1 문자로 보존해 내용이 사라지지 않게 한다.
- **잘린 파일**: 크기 제한으로 잘린 파일은 저장할 때 한 번 확인받는다.
- **외부 변경**: 열 때 기록한 mtime과 크기가 디스크와 다르면 저장할 때 덮어쓸지 묻는다. 이 편집기가 방금 저장한 결과는 외부 변경이 아니다. 이전 상태를 확인할 수 없으면 변경으로 보지 않고 저장한다.
- **종료** (`C-x C-c`): 미저장 변경이 있으면 확인한다.
- **파일 잠금 없음**: 잠금 파일을 만들지 않으며 "File in use" 질문도 없다.

## 9. 검색과 치환

- 기본은 문자열 증분 검색이다. `C-s`로 앞으로 찾는다. 글자를 칠 때마다 이동하고, `C-s`를 다시 누르면 다음 일치로 간다.
- 뒤로 검색(`isearch-backward`)과 치환(`query-replace`)은 `M-x`로 호출한다.
- 대소문자 구분과 정규식은 모드가 아니라 명령으로 고른다. 정규식 명령은 `isearch-forward-regexp`, `isearch-backward-regexp`, `query-replace-regexp`다. 대소문자는 설정 `case-fold-search`(기본 `true`)로 정한다. 키 바인딩은 Lua로 바꾼다.
- 정규식: `.`, `[...]`, `[^...]`, `*`(바로 앞 원소 반복), `^`, `$`. 일치는 한 줄 안에서만 한다. 치환 문자열의 `&`는 일치한 문자열 전체로 바뀐다. 정규식이 아닌 치환(`query-replace`)에서는 `&`와 `\&`가 그대로 문자다. 정규식 치환(`query-replace-regexp`)에서는 `\&`가 `&` 문자다.

## 10. 보기 전용

- 모드 시스템은 없다. 대소문자와 정규식은 9절의 명령 인자다.
- **보기 전용 플래그**: 버퍼마다 하나다. 켜면 내용을 바꿀 수 없다. `view-mode`로 켜고 끄며, 키는 두지 않는다. 상태 줄에 표시한다.
- 시작 옵션 `-v`는 없다. 파일을 연 뒤 `view-mode`를 호출한다.

## 11. 한글과 UTF-8

- 읽기: UTF-8. 과도하게 긴 형식도 읽는다. 저장: 읽은 바이트는 그대로 저장한다. 입력한 문자는 가장 짧은 표준 형식으로 인코딩한다.
- 커서는 문자 경계를 따라 움직인다. 한 글자가 여러 바이트여도 중간에 멈추지 않는다.
- 표시 폭:
  - 탭은 다음 탭 위치까지 차지한다.
  - 제어 문자는 2칸, C1 제어 문자(0x80~0x9F)는 3칸이다.
  - 한글, CJK 등 전각(East Asian Wide/Fullwidth) 문자는 2칸이다.
  - 결합 문자(Mn, Me), 한글 자모 중성·종성(U+1160~11FF), ZWJ 등은 0칸이다. 커서는 문자 단위로 움직인다.
  - 그 밖의 문자는 1칸이다.

## 12. 확장과 설정 (Lua)

- 설정과 확장은 Lua로 한다. 파일은 `~/.config/neonemacs/init.lua`이며, `XDG_CONFIG_HOME`이 있으면 `$XDG_CONFIG_HOME/neonemacs/init.lua`다. 세 플랫폼 모두 같은 규칙이다.
- **공개 API는 최소로 한다.** 공개한 API는 호환성 약속이다. 노출하는 것은 다섯 함수뿐이다.
  - `bind(keys, command)`: 키 바인딩 추가와 변경
  - `command(name, function)`: 명령 등록
  - `run(name)`: 명령 실행
  - `get(name)` / `set(name, value)`: 설정 값 읽기와 쓰기
- 버퍼 텍스트, 이벤트 훅, 버퍼·창·파일 시스템은 공개하지 않는다.
- 생존 집합 밖의 키는 Lua 설정으로 추가할 수 있다.

### 시작 방식

- 파일 인자는 모두 백그라운드 버퍼로 열고, 첫 번째 파일을 화면에 보인다.
- 유일한 시작 옵션은 `+n`(n번째 줄에서 열기)이다. `init.lua`가 있으면 시작할 때 자동 실행한다.
- `@파일`과 `-v`는 없다. 보기 전용은 `view-mode`로 연다 (10절).

## 13. 플랫폼

- Linux, macOS, Windows를 지원한다 (2절).
- Windows 콘솔은 `C-_`, `C-/`, `C-SPC`를 POSIX 터미널과 다르게 보낼 수 있다. 생존 집합 키는 세 플랫폼 모두에서 같은 동작을 해야 한다.
- 메모리 할당 실패 같은 치명적 오류는 메시지를 남기고 종료한다.

## 14. 동작 원칙

1. **단순함과 이식성을 우선한다.** 기능보다 크기와 이식성을 지킨다.
2. **인지 부하를 줄인다.** 키는 적게 두고, 나머지는 익숙한 Emacs 명령 이름으로 `M-x`에서 부른다. 새 규칙은 Emacs에 없을 때만 도입한다.
3. **입력에 지연이 없어야 한다.**
4. **저장 전에 묻는다.** 잘린 파일, 외부 변경, 미저장 종료는 먼저 묻는다.
5. **판단할 수 없으면 막지 않는다.** 이전 상태를 알 수 없는 파일은 차단하지 않고 저장한다.
6. **저장 사고를 막는다.** 저장 전 편집 기록은 영속 undo로 남긴다.
7. **데이터 불변식을 지킨다.** 버퍼 풀의 최소 버퍼 보장, 창 분할 트리의 선택 유효성, UTF-8 및 커서 경계, 단일 키/접두사 정규 키 시퀀스, 크래시 복구 바이너리 스키마 등 모든 도메인 규칙을 데이터 구조와 타입 수준에서 강제하여 불가능한 상태 전이와 패닉을 원천 배제한다.

## 15. 한계와 주의점

- Emacs와 독립된 편집기다. Emacs 구현의 매크로 문법과 호환되지 않는다.
- 키 호환은 3절 범위에서만 보장한다. `C-x b`, `C-x o`, `C-x 2`가 없어 근육 기억이 깨질 수 있다.
- `C-/`는 많은 터미널에서 `C-_`로 전송된다. 그래서 두 키를 함께 바인딩한다.
- 영속 undo는 저장 전 강제 종료 시 미저장 편집을 복구하지 못한다.
- 한글 IME 조합 표시는 터미널에 따라 다르다.
